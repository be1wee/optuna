# Подготовка к защите

## Сначала разобраться

- Study — вся серия попыток; Trial — одна попытка.
- objective — функция, вычисляющая результат для выбранных параметров.
- Самплер выбирает параметры; Storage сохраняет параметры и результаты.
- Цель демо: приблизиться к x=2, y=-1, где формула равна нулю.

## Показ за 5–6 минут

1. Открыть common.py: показать формулу и два suggest_float.
2. Запустить steps.py: ask создаёт попытку, objective оценивает, tell сохраняет результат.
3. Запустить run.py с --sampler random, затем с tpe. Показать вызовы sample_independent и sample_relative.
4. В отладчике перейти из suggest_float в Trial._suggest установленной Optuna.
5. Запустить custom.py: тот же objective с собственным LocalSearchSampler.

## Три метода BaseSampler

- infer_relative_search_space: какие параметры можно выбирать совместно.
- sample_relative: вернуть набор значений. Пустой словарь передаёт выбор independent-ветке.
- sample_independent: выбрать отдельный параметр.

before_trial и after_trial — хуки жизненного цикла.
TracingSampler делегирует их исходному сэмплеру и печатает итог попытки.

## Изменения на защите

- Изменить диапазон: low/high в suggest_float.
- Изменить число попыток: range(5) в steps.py или n_trials=15 в run.py/custom.py.
- Сменить алгоритм: --sampler random/tpe в run.py.
- Изменить число начальных проб: n_startup_trials в run.py/custom.py.
- Изменить ширину локального поиска: radius в custom.py.
- Изменить искомую точку: числа 2 и -1 в формуле common.py.

## Решение и ограничения

Study/Trial зависят от BaseSampler: можно менять алгоритм без изменения задачи.
TracingSampler оборачивает другой сэмплер и добавляет логирование.
LocalSearchSampler возвращает {} в начале, поэтому Trial использует случайный fallback.
Он поддерживает только одну цель и float без log/step. Радиус постоянный.
Результат за 15 попыток не обязан быть нулём; сравнение нескольких запусков не доказывает
превосходства алгоритма.

UML показывает только часть Optuna, нужную для этого сценария.
